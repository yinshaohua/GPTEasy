# 供应商管理界面合同

<!-- release-contract: desktop-consumer-control=prohibited -->

本合同描述 v0.1 之后已经确认的供应商管理界面目标。

## 信息架构

- 左侧导航将“供应商”改为“供应商管理”，并作为默认页面。
- “会话管理”保留为禁用导航项并标记“即将支持”，本轮不提供空页面。
- 原“Codex 环境”页撤销；其供应商切换、OpenAI 登录模式、恢复以及环境异常处理能力迁入“供应商管理”。
- 供应商目录与详情编辑使用前后两级页面，不使用左右栏。
- 主窗口默认尺寸为 `1120 × 620`，最小尺寸为 `680 × 520`，并允许用户缩放。
- 供应商管理页顶部不显示 Codex 环境状态栏。环境实际状态仍在后台读取并驱动供应商模式、OpenAI 登录模式、恢复、接管和管理冲突保护；当前供应商由目录行内状态表达。

## 供应商目录

- 使用紧凑的表格式列表。默认窗口下摘要与行级操作保持同一行；接近最小宽度时每条记录可以改为两行。
- 每条目录记录显示供应商名称、BASE_URL、默认模型、验证状态、当前使用状态和行级操作。
- 名称与状态标签优先获得横向空间，BASE_URL 与默认模型紧凑截断，并保留可访问的完整文本。
- 已保存的供应商显示“已验证”；当前供应商在此基础上额外显示“当前使用”，二者不是互斥状态。
- DayWay 永久位于第一项；其他供应商按配置先后保持用户可调整的顺序，不因验证、切换或名称变化自动重排。
- 行级操作为“验证”“修改”“删除”和“切换”。只有明确点击“切换”才修改当前用户 Codex 环境；点击记录本身不切换。
- 当前供应商的切换操作显示为不可点击的“当前使用”。当前供应商不可删除。
- “验证”执行完整供应商验证，不提供会把连通性误报为 Codex 兼容性的轻量测试。
- 供应商仍只保存一个默认模型。获取模型用于提供默认模型的可选项。
- 列表标题行提供带加号图标的“添加供应商”，进入空白详情页；DayWay 的“配置”进入预填身份信息的同一详情流程。
- 其他供应商支持用户通过行首拖拽手柄调整顺序。DayWay 不可拖动。排序不提供键盘操作；这是对 v0.1 全键盘合同的明确例外，其他供应商操作仍须支持键盘。
- 删除普通供应商后，其余记录保持相对顺序并紧凑化；重新添加同名供应商视为新供应商并排在末尾。
- 供应商顺序同时用于供应商管理列表和托盘菜单。未配置的 DayWay 模板不进入托盘；配置后在两处均置顶。

## 推荐供应商模板

- DayWay 作为推荐供应商模板永久排在目录最前面；完成配置、验证和保存前，它不属于供应商目录。
- DayWay 固定显示名称为 `DayWay`，预填 BASE_URL 为 `https://dayway.site/v1`，且不允许修改名称。它不预设模型。
- 未配置模板显示“待配置”，不提供切换操作。
- DayWay 提供“访问官网”按钮，通过系统默认浏览器打开 `https://dayway.site`。
- 官网链接不携带 API Key、供应商配置或跟踪参数；应用内不嵌入供应商网页。
- DayWay 验证并保存后原地成为已验证供应商，继续置顶并保留“推荐”和官网入口；删除后恢复为未配置模板。
- 应用升级可以直接更新尚未配置的 DayWay 模板；已经保存的 DayWay 不被静默覆盖。推荐地址变化时提示用户采用，采用后仍须重新验证并明确保存或保存并应用。

## 目录底部操作

- 列表底部使用一个无卡片的操作区，不显示“其他环境供应商操作”或“当前 Windows Codex 环境操作”分组标题。
- 操作区从上到下各占一行：“选择 WSL2 供应商”、“导出 Linux 脚本”、“切换到 OpenAI 登录模式”。主界面不提供“恢复上次配置”入口。
- “选择 WSL2 供应商”所在行展示首个可管理发行版的实际当前供应商名称、BASE_URL 和默认模型；弹窗中的供应商选择只是待应用目标，不能在应用成功前显示为当前供应商。WSL2 应用直接使用该供应商保存并验证过的默认模型，不另设模型选择。
- “导出 Linux 脚本”在至少存在一个已验证供应商时可用，导出当前全部已验证供应商的 Linux 供应商快照。“切换到 OpenAI 登录模式”按 Windows 环境实际状态决定是否可用，并使用与 Windows 供应商切换相同的简短确认。

## Linux 脚本导出

- 点击“导出 Linux 脚本”后选择 Bash 4+ 或 Zsh 5+，一次只生成一种 shell 的独立文件；建议文件名分别为 `gpteasy.sh` 和 `gpteasy.zsh`。
- 导出前说明文件包含全部已验证供应商的敏感凭据，只能保存到受信任的当前用户位置。保存路径已存在时必须再次确认覆盖，取消或失败不得改动原文件。
- 导出完成后介绍直接执行脚本、source 到当前会话，以及在 `.bashrc` 或 `.zshrc` 中 source 以便长期使用；GPTEasy 不自动修改任何 shell 启动文件。
- 用法说明列出 `gpteasy`、`help`、`current`、`restore`、`info` 和 `unlock` 的主要效果，并说明 `gpteasy help`、`gpteasy --help` 与 `gpteasy -h` 等价。
- 直接执行和 source 使用相同的公开入口。source 本身不创建目录、读取或修改 Codex 配置；只有用户调用 `gpteasy` 并明确选择供应商后才写入。

## WSL2 供应商选择

- 点击“选择 WSL2 供应商”后重新探测发行版，弹窗一次只允许选择一个可管理发行版和一个已验证供应商。默认选择所选发行版的实际当前供应商；切换发行版、核验实际状态或应用失败后，选择框都按刷新后的实际状态重置。
- 发行版选择只列出当前可管理的发行版，不渲染已移除、基础设施、暂时不可探测、版本不支持或无法安全解歧的记录，也不提供空的“请选择发行版”选项。
- 确认前说明目标发行版、目标供应商、只修改默认用户的 `config.toml` 和命令式凭据工件、绝不修改 `auth.json`，以及运行中的 Codex 需要用户手动重启。
- 普通刷新不启动 Stopped 发行版；“刷新实际状态”、供应商应用和删除前核验只有在用户明确允许后才可临时启动。配置操作结束后显示“等待自然停止”并只读观察最多 10 秒，不强制终止发行版；未自然停止时保留 Running 并提示 WSL2 环境变化。
- Running 发行版刷新时读取实际管理区块和凭据内容，以供应商 ID显示当前身份；同一 ID但名称、地址、模型或凭据不同显示“当前，有更新”，旧版管理区块显示“当前，旧格式”。
- 应用和失败状态保留在弹窗内；应用成功后自动关闭弹窗，只留下短暂脱敏页面反馈。取消仍由用户明确关闭；不显示 API Key、配置正文、命令行或 guest writer 原始输出。
- WSL2 环境变化、管理冲突或供应商 ID 不存在时停止写入并要求刷新；不自动重试、替换目标、迁移未知 schema 或把同名新发行版当作旧环境。

## 供应商详情

- 新建和修改字段只有名称、BASE_URL、API Key、获取模型和默认模型选择。
- API Key 默认隐藏；完整显示和复制仍需要用户明确操作。
- 获取模型仍放在模型字段附近，不放入页面底部操作栏。
- 底部操作固定为一行：左侧是“验证供应商”和验证状态，右侧是“返回”以及“保存”或“保存并应用”。验证进行时原按钮变为“取消验证”，布局不移动。
- 无修改时直接返回。存在未保存修改时，返回操作提供“放弃修改”和“继续编辑”；不保存持久草稿。
- 保存按钮保持可点击。关键配置未验证时，点击后提示必须先验证，并提供“开始验证”和“继续编辑”，不允许绕过验证保存。
- 当前供应商的关键配置修改仍使用可恢复的“保存并应用”，确认后同时更新供应商目录与当前用户 Codex 环境，并以返回的环境实际状态更新“当前使用”。

## 供应商验证

- 验证使用模态弹窗，依次显示模型确认、Responses API 流式响应和工具调用闭环的状态。
- 当前执行项使用克制的小动画表达后台仍在工作，不显示无法证明的百分比。Windows 启用“减少动态效果”时改用静态状态表达。
- 验证期间不能通过遮罩或 Esc 意外关闭弹窗；用户可明确执行“取消验证”。
- 验证完成或失败后弹窗保持打开，由用户执行“完成”或“返回修改”。
- 失败显示简短原因和可展开的脱敏技术详情，不显示 API Key、完整请求或响应正文。
- 地址探测只在同一协议、主机和端口内尝试有限候选：原地址、补上或移除末尾 `/v1`，以及剥离误填的 `/models`、`/responses` 或 `/chat/completions`。不得跨域、更换协议或遍历任意父路径。
- 地址候选严格串行尝试。只有端点路径可能错误时才继续；认证失败、限流、TLS、安全策略或响应协议错误不触发地址猜测。
- 地址探测从“获取模型”开始。候选地址能发现模型后，只作为尚未采用的建议地址供后续选择模型和完整验证使用。
- 只有候选地址通过完整供应商验证后，才展示原地址和建议地址并询问是否采用。未经用户同意不得回填或保存建议地址。
- 用户拒绝采用建议地址时，不得用候选地址的验证结果保存原错误地址。
- 对已保存供应商采用建议地址时，只将已验证候选回填到详情页；用户仍须明确执行“保存”或“保存并应用”。
- 当前步骤显示小型旋转进度图标和已用时间；等待超出阶段预期时显示“仍在等待供应商响应”。已完成、失败和未开始步骤分别使用勾、错误图标和静态状态。
- 详情页底部状态描述当前候选配置：尚未验证、验证中、验证通过或验证失败。标题附近另行显示记录级的“已验证”和“当前使用”。

## 桌面消费者

- 左侧导航只包含页面项，不提供启动或重启 ChatGPT/Codex 的独立命令。
- ChatGPT/Codex 桌面版和 Codex CLI 都只是当前用户 Codex 环境的消费者。消费者扫描只用于身份分类、环境实际状态和被动待重启协调，不启动、关闭、终止、激活或重启任何消费者。
- 供应商切换、OpenAI 登录模式切换和保存并应用只完成安全配置写入并返回环境实际状态；运行中的消费者继续使用旧配置并产生被动待重启状态。
- 待重启由消费者在其原入口自然退出并重新运行后清除；GPTEasy 不提供立即重启、强制关闭确认、激活结果或重启成功条件。

## 操作反馈

- 从目录直接验证供应商时，结果完整保留在验证弹窗中。验证成功后更新验证时间数据与验证证据，并短暂显示页面内成功反馈；目录不显示验证时间，不发送系统通知，也不切换供应商。
- 已保存供应商重新验证失败不清除原验证证据。当前页面可显示非持久的“最近验证失败”，应用重启后仍按已验证供应商展示。

## 环境状态与确认

- 没有其他已保存供应商时，DayWay 模板仍作为首行显示“推荐”和“待配置”，BASE_URL 使用预填值，模型显示“尚未选择”，操作为“访问官网”和“配置”；其下显示“尚无其他供应商”。
- 设置页和托盘选择任何非当前供应商时都使用同一个简短确认。确认只显示目标供应商和运行中消费者可能继续使用旧配置的风险，不显示具体 Codex 工件、字段或重启选项；无法安全解析时仍不提供强制覆盖。
- OpenAI 登录模式继续禁用重复切换到该模式的操作，所有已验证供应商仍提供“切换”。切换供应商、OpenAI 登录模式和保存并应用成功后立即采用后端返回的环境实际状态；失败后先重新读取环境实际状态，再显示错误，不自动重试、合并或覆盖外部修改。
- 供应商切换、OpenAI 登录模式切换、恢复和保存并应用分别显示自己的忙碌状态，不让无关控件显示旋转进度。
