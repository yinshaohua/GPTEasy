# 首个可验收版本采用 Windows x64 垂直切片

GPTEasy 不再等待原规划中的 88 项能力和全平台矩阵全部完成后才首次交付。首个可验收版本只面向 Windows 10 22H2 或更高版本的 x64 系统，贯通标准供应商创建与验证、当前用户 Codex 环境安全切换、外部配置保留、备份恢复、待重启、本地状态以及必要的设置界面和托盘操作；Windows ARM64、macOS、WSL2、Linux 切换脚本、自动更新、完整发布签名矩阵和 DayWay 推荐入口延后为独立里程碑。这样优先验证核心用户价值，并避免平台与发布基础设施在产品可用前主导开发。

验收采用两层证据：自动化测试通过本地模拟供应商、隔离 Codex 目录和进程 fixture 覆盖成功、失败与崩溃恢复；发布前人工 UAT 在一次性 Windows x64 当前用户环境中，使用当前支持的真实 Codex CLI、桌面 Codex 和至少一个真实标准供应商完成验证、切换及新进程读取。模拟结果、未安装消费者场景或旧 Spike 证据都不能单独替代真实闭环。

首个闭环必须从配置不存在、已有 OpenAI 登录模式、已有有效外部供应商配置、TOML 损坏或供应商字段归属不明四种初始状态验收。前两种不得因启动、验证或保存而写入，外部配置只有展示范围并明确确认后才能接管，损坏或歧义状态必须无写入拒绝；真实 UAT 至少走通配置不存在和有效外部配置两条路径。

自动化闭环至少建立两个名称和不可变 ID 不同的已验证供应商，证明目录保存、当前供应商切换、托盘快捷切换和失败后旧状态保留；人工 UAT 至少使用一个真实标准供应商，第二个供应商可以在安全测试服务或同一服务的独立命名记录上完成。

跨 SQLite、配置文件和凭据载体的崩溃恢复是首版发布门禁。测试必须在未完成操作各持久化阶段注入失败，重启后根据旧指纹、新指纹或第三种指纹分别收敛到旧状态、新状态或管理冲突；验证失败和用户取消不创建操作、备份或配置写入。
