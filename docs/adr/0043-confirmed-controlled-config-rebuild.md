# 管理冲突允许确认后的受控配置重建

普通接管仍只处理能够安全解析并保留未知字段的 Codex 配置。配置或凭据工件损坏、结构歧义或无法安全迁移时，GPTEasy 不猜测原内容，也不自动覆盖；供应商管理页提供独立的“强制设置”入口，让用户从供应商目录选择一个已验证供应商并重新执行完整验证。

验证成功后，后端先按环境最新 revision 再次检查并尝试普通安全应用。只有失败类别明确要求重建时，界面才显示第二次确认，说明将创建带时间戳的备份并重建最小可用 Codex 配置。用户确认后，后端只根据已验证供应商记录生成受控配置和凭据，不接受前端传入的任意路径、文件正文或 shell 命令；写入继续使用单个未完成操作、备份、原子替换和失败恢复协议。

受控重建有意放弃无法证明可保留的损坏内容，因此它不同于 ADR-0017 的结构化接管和 ADR-0019 的安全重新接管。操作必须可审计地记录“重新验证、要求重建、用户确认、备份、写入和结果”等阶段，但日志和诊断不得包含 API Key、完整配置或用户路径。并发状态变化、备份失败、写入失败或写后校验失败一律停止并恢复，不把部分结果报告为成功。
