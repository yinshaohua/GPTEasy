# 缺失会话索引优先由 App Server 协调并受限事务补建

会话索引补建先用干净的兼容 App Server 扫描协调；只有身份完整、明确属于用户交互会话且补建元数据完整的有效 rollout 在协调后仍缺少索引，并且运行时精确识别到支持矩阵中的 SQLite schema 时，才允许在单库事务中补行。支持矩阵使用完整建表定义的规范化指纹，并拒绝额外的显式索引或触发器；同一 thread ID 对应多个 rollout 时整体按歧义身份跳过。未知、未来、损坏或歧义 schema 严格跳过；后备流程不删除、合并或清理任何现有索引，并与 rollout 原子替换分别记录可判断、可重试的恢复阶段和数据库哈希，最后仍由干净 App Server 验证全供应商视图、当前供应商过滤、数量、thread ID 与归档状态不变量。

本决策扩展 ADR-0046 的会话可见性修复例外，仅覆盖缺失索引的受限补建；常规会话读取、搜索、归档和删除继续遵循 ADR-0034，只通过官方 App Server 执行。
