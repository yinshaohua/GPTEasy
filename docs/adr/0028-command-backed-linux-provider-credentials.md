# Linux 环境使用命令式供应商凭据

独立 GNU/Linux 导出物和桌面 GPTEasy 管理的 WSL2 发行版环境统一使用 Codex 自定义供应商的 `auth.command` 接口提供 API Key：用户明确选择供应商时，写入方只为被选择的供应商创建按来源 ID和供应商 ID隔离、权限为 `0600` 的 Linux 凭据工件，配置通过 `cat` 引用该工件。加载导出物不产生文件副作用，API Key 不进入命令参数、`config.toml`、配置备份或日志；WSL2 供应商切换也不再修改 `auth.json`，从而保留其中的 OpenAI 登录及其它字段。

旧 Spike 使用的 `experimental_bearer_token` 虽然简单，但官方不推荐且会把 Key 复制到配置和每份备份；结构化修改 `auth.json` 则需要 jq、Python、额外二进制解析器或不安全地整体覆盖文件。命令式凭据保留 Bash/Zsh 导出物独立运行、无额外解析器的边界，同时使用 Codex 的正式凭据扩展点。

当前已验证的最低基线是 `codex-cli 0.147.0`。Linux 导出物允许目标环境尚未安装 `codex`：用户明确选择供应商后仍可预先创建默认 Codex 环境、命令式凭据和配置，待用户自行安装兼容 CLI 后读取。若 `codex` 已位于目标环境的 `PATH`，则必须在任何安装、备份或配置写入前确认版本不低于该基线且版本输出可以识别；版本过低、输出无法识别或命令执行失败时停止，不能退回实验性凭据字段。桌面 WSL2 应用流程仍以目标发行版中可验证的 CLI 版本为兼容性门禁。

导出脚本管理当前执行用户的 `CODEX_HOME`，而不是全局 `codex` 安装目录。既有目标环境、`config.toml` 最终目标及 Linux 私有状态必须属于当前用户；脚本不因组权限、ACL 或 root 身份跨用户写入。root 可以管理自己的 `/root/.codex`，但需要管理其他用户时必须切换到目标用户身份。已有用户所有文件权限过宽只产生非阻断警告；新建凭据、恢复点、锁和临时文件始终使用私有权限。脚本不自动执行 `sudo`、`chown` 或 `chmod`。

只要当前配置或最近五个恢复点仍引用某个 Linux 凭据工件，该工件就不能被删除；切换、一步撤销和凭据清理必须共同维护这一引用关系。恢复成功后消费对应恢复点，只有不再被当前配置或剩余恢复点引用的凭据工件才能清理。脚本检查凭据工件的文件类型、存在性、所有者和权限；当前用户所有但权限过宽时警告，不保存或比较 API Key 哈希。
