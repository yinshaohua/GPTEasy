# 诊断修复只采用唯一且一致的本地证据

缺失 `custom` provider 定义只能通过本机诊断报告中的预览和用户确认修复。当前配置候选必须保留明确的 `custom` 历史名称，并与 GPTEasy 最近应用的已验证供应商 ID、名称、服务地址、默认模型、API Key 和验证组合指纹完全一致；不能仅把当前可用供应商推断成 `custom`。备份候选必须来自经完整性验证的 GPTEasy 备份中的同名 `model_providers.custom` 定义，并与当前模型和 API Key 凭据一致。`CODEX_HOME` 指向其它环境、多个不同候选、凭据缺失或字段无法确认时不写入。确认后复用单个未完成配置操作、完整备份、并发指纹和原子替换协议，写入或校验失败立即回滚，进程中断则在下次启动恢复原配置，而不把半完成修复前滚为成功。
