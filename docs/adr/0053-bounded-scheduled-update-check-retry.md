# 定时更新清单失败后有限重试

## 状态

已采纳。本文取代 ADR-0039 的定时清单失败后只允许手动重试策略。更新源和发布流程继续遵循 ADR-0045。

## 决定

Windows x64 启动检查和每日检查共用一个进程内调度。清单请求遇到连接故障、超时或响应中断，或收到 HTTP 429、500、502、503、504 时，从该次失败结束起分别等待 30 秒、2 分钟和 10 分钟，最多再执行三次。每次都从配置的 Gitee 清单地址开始。有效的 `Retry-After` 可以推迟自动检查。短周期重试成功、额度用完或遇到不可重试的故障时，恢复 24 小时检查节奏。

手动检查可以在等待期间立即发起，与后台检查共用互斥状态。手动成功会取消剩余重试，并从本次成功起重新计时。手动失败保留已安排的检查，有效的 `Retry-After` 可以推迟该检查。更新窗口展示短周期重试时间。应用退出时释放调度状态。

证书校验失败、无效清单、安装包下载失败和验签失败沿用现有手动处理入口。已有验签通过的待安装更新在检查失败后仍可安装。更新安装继续由用户确认。

问题日志记录触发来源、失败阶段、错误类别、尝试序号、可用的 HTTP 状态或系统错误码和短周期重试时间。日志字段仅使用结构化数据，签名参数、完整跳转地址和响应正文留在请求处理中。

## 原因

本机复测发现，从 Gitee 跳转到 Raw 内容主机后偶尔发生连接重置，之后重新请求可以取得有效清单。显示失败和下次尝试时间能让用户了解当前状态，有界间隔能在临时网络故障后恢复检查，并限制持续故障时的请求量。
