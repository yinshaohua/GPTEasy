# 首版管理用户交互会话并提供永久删除

首版会话管理只列出当前 Windows 用户 Codex 环境中的用户交互会话，包括用户从 ChatGPT/Codex 桌面版、Codex CLI、IDE 或其他交互入口直接参与的会话。查询必须显式限定 App Server 的来源类型；exec、子代理、自动化及其他内部来源不进入列表，也不通过默认筛选器暴露。

首版同时提供可恢复的归档/取消归档和不可恢复的永久删除，两者必须使用不同的名称、视觉层级和确认流程。永久删除只调用官方 App Server 方法，不制作或恢复私有 SQLite 行及 rollout 文件备份；官方协议没有撤销能力时，界面不得暗示回收站、恢复期或撤销保证。

官方永久删除可能一并删除所选根会话派生出的会话，确认界面必须在执行前明确披露影响。能否在删除前可靠列出全部派生会话，仍需通过协议能力和真实数据验证；不能完整预览时必须明确说明，而不是显示可能不完整的确定数量。

外部 ChatGPT/Codex 桌面版、Codex CLI 或 IDE Codex 消费者仍在运行，或者消费者状态无法可靠确认时，会话管理保持可浏览，但禁用归档、取消归档和永久删除。GPTEasy 自有的会话服务进程必须从消费者判断中排除。这个首版限制接受较粗粒度的全局只读状态，以避免独立 App Server 与其他进程并发修改同一会话；未来只有在跨进程实验能够证明安全并形成新决策后才能放宽。

上述外部消费者阻断规则已由 ADR-0036 取代；本 ADR 的其他会话范围、归档和永久删除规则继续有效。

永久删除既允许单个会话操作，也允许用户通过列表左侧复选框选择多个已加载会话后批量发起。批量永久删除必须使用独立的危险操作按钮和确认流程，明确列出所选会话、不可撤销性以及派生会话风险；不提供删除当前页或全部筛选结果。官方协议没有批量事务时，归档、取消归档和批量永久删除都必须逐项执行并展示逐项结果；部分失败不得显示为整体成功，失败项保持选中以便再次确认后重试。

首版使用“会话”和“已归档”两个页签，共用搜索与适用的筛选条件。会话页提供归档，已归档页提供取消归档；永久删除在两类会话中都保持独立的危险操作，不混入归档动作。

默认列表跨全部项目展示用户交互会话，按最近更新时间倒序排列，并提供项目和会话供应商筛选。分页沿用 App Server cursor，界面使用明确的“加载更多”，不模拟无法由 cursor 支持的随机页码；筛选或搜索变化时从首个 cursor 重新查询。

列表只读取会话元数据，用户打开会话时再按需加载完整详情。详情展示用户和助手内容，命令、工具调用及其结果作为可展开的活动呈现，默认折叠以保持阅读连续性；详情不提供继续会话、追加消息或审批入口。首版提供 Markdown 导出，导出内容来自本次 App Server 读取结果，不直接解析 rollout 文件。

单项永久删除确认展示会话标题、项目、不可撤销说明和派生会话风险，并在同一确认流程提供“先导出 Markdown”。批量永久删除确认展示全部所选会话标题、不可撤销说明和派生会话风险，不在同一流程逐项弹出导出位置。导出不是删除前置条件；用户可以取消导出或直接使用明确的危险操作按钮确认删除，不要求输入标题或会话 ID。
