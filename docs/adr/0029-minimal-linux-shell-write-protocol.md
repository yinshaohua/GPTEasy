# Linux shell 不保存跨操作校验证据

独立 Linux 脚本以 `${CODEX_HOME:-$HOME/.codex}` 为目标环境，并把凭据工件、恢复点、临时文件和写锁隔离在其 `.gpteasy-shell/` 目录。切换和恢复通过带 owner 类型、随机 token、PID、进程启动信息及操作类型的原子锁目录串行执行，读取配置后只在内存中保留 SHA-256，并在替换前复核；配置仍使用目标文件同目录候选和原子替换。

脚本不保存已应用证据、组合指纹、配置旧/新哈希、恢复点完整性哈希或未完成操作。管理区块使用非敏感的 Linux 导出 ID和供应商 ID区分同一快照的当前供应商与其它快照；中断后只清理未提交的临时文件，不提供跨崩溃协调。恢复点只保存恢复所需的原配置内容、原存在性、symlink 目标和凭据引用；`restore` 经用户确认后覆盖当前配置，不能判断上次切换后发生的外部修改。

`config.toml` 是 symlink 时，脚本保留链接，并在一次操作内反复确认它仍指向同一当前用户所有的普通文件，再在最终目标所在目录原子替换。hardlink 无法同时保持其它目录项同步和原子替换，因此链接计数大于一时停止。私有目录、凭据工件、恢复点和临时文件不允许 symlink 或 hardlink。

在 WSL2 共同管理环境中，`restore` 可能覆盖桌面 GPTEasy 或其它导出脚本在恢复点之后完成的写入。脚本必须先取得共享锁，展示当前实际状态和恢复目标，明确警告这种覆盖可能，再要求用户确认；它不根据来源 ID猜测哪一份配置更新，也不因写入来自桌面而自动拒绝恢复。

锁竞争立即失败并返回非零状态，脚本只显示非敏感的持锁方、操作类型和重试建议，不自动等待。`gpteasy unlock` 只能在确认 PID 与进程启动信息均已失效后，经用户再次确认删除 shell 崩溃留下的锁；活动锁及 owner 为桌面的锁一律拒绝解锁，后者必须交由桌面 WSL2 Saga 恢复。
