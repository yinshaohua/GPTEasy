# 独立刷新受管模型目录，并为确认未识别的模型提供兼容档位

升级 Codex 或重启 daemon 不会重新生成 GPTEasy 的 JSON。对同一个原生 CLI，隔离目录的 `model/list` 和现有 JSON 可以分别显示六档和零档。不要以「daemon 已刷新」代替目录提交或客户端已重载的证据。

## 选择器策略

| 当前目标环境的证据 | 目录行为 |
|---|---|
| 精确模型有档位 | 使用探测得到的完整列表，包括实际返回的 max、ultra。 |
| 有适用的已登记供应商兼容规则 | 使用该规则，不追加通用档位。 |
| 完整探测成功，但没有找到精确 ID（NotFound） | 客户端兼容策略 v1：low、medium、high、xhigh，默认 high。描述明确标为未经供应商验证。 |
| 明确无档位、冲突、探测失败、快照不完整或来自其他环境 | 不伪造可选档位；独立刷新不把原有有效档位覆盖为空。 |

此表修订 ADR-0049、0051 对 NotFound 的处理。四档是项目选择的兼容范围，不代表所有供应商都接受这些值。共享生成器用于原生、WSL 以及导出中有完整匹配快照的条目。Windows 不引用 WSL 的目录。

## 如何刷新

启动 GPTEasy 或重新运行本机诊断。发现受管目录过期后，点击「刷新模型能力」并确认。复用本机 CLI 版本、可执行文件指纹和模型集合绑定的快照，失配时重新探测。无需强制设置供应商，不联网重验凭据，也不自动重启 Codex。当前实现只在原生环境提供独立修复入口；WSL 按其自身应用流程生成目录。

提交前重新生成预览，核对活动供应商、配置指针以及旧、新目录；无关 TOML 注释不使预览失效。只接受可识别的生成字段，保留模型集合和顺序；手工修改其他目录字段时拒绝覆盖。确认后备份原目录，原子替换并回读验证。已有显式根级强度（包括 none）不因目录修复被改写；需要时在重启后的模型选择器选 high。目录默认值不是强制重设用户偏好。

## 验证

普通回归覆盖精确模型、确认未识别、显式无档位、环境不匹配和旧图片目录。真实 Windows 探测用例在临时目录构造旧目录，用所选 CLI 重新加载修复结果，不修改用户环境：

~~~powershell
$env:GPTEASY_CODEX_EXECUTABLE = '<原生 codex.exe 的绝对路径>'
cargo test --manifest-path src-tauri/Cargo.toml --test diagnostic_report real_cli_refreshes -- --ignored
~~~
