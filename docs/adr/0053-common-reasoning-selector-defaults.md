# 通用思考档位兼容默认值

2026-10-02，用户要求恢复 Codex 中的思考深度选择，优先采用免逐模型配置的通用默认值。本机 Codex CLI 已由旧证据中的 0.157.1 更新为 0.159.3。隔离 App Server 实测和官方选择器源码表明：`supported_reasoning_levels: []` 没有可选档位；`default_reasoning_level: null` 被转换为 `none`，切换模型可以把该值持久化为根级配置。删除列表字段则触发目录解析失败。

## 决策

### 权威配置与派生工件

- `providers` 和 `provider_model_catalog` 属于 **GPTEasy 自己的 SQLite**，分别保存供应商配置和绑定验证组合的完整模型发现快照；它们继续作为权威来源。应用前必须检查快照格式、非空模型集合和验证指纹，缺失、损坏或失效时要求重新验证，不回退到默认模型或磁盘目录。
- `config.toml`、凭据工件及 `gpteasy-model-catalog.json` 是应用供应商时输出给 Codex 的派生工件；`model_catalog_json` 只是配置中的目录指针，不替代 GPTEasy 的持久化，也不证明供应商验证成功。已有目录仍须备份、参与并发修订和恢复，不反向导入为已验证快照。
- 本决策不涉及删除、迁移或修改 Codex 自身的 SQLite。SQLite 与 JSON 并不冲突：前者管理 GPTEasy 的配置与验证事实，后者满足 Codex 消费者的目录协议。

### 客户端兼容默认值

- 当前用户 Codex 模型目录对所有已发现模型使用一套 `common-reasoning-selector-v1` 兼容默认值：`low`、`medium`、`high`、`xhigh`，默认 `high`。保持完整目录 schema，不省略列表，不再生成空列表或 null 默认值。
- 这是客户端选择器兼容策略，与 ADR-0050 的图片输入兼容声明同属允许请求到达上游的策略；不表示供应商或单个模型已验证支持四档。能力描述仍为“供应商已发现模型，能力未识别”，不按模型名推断能力，也不在请求链路中新增代理或档位转换。
- OpenAI、DeepSeek、兼容供应商和新模型 ID均使用同一模板，无需维护逐模型 profile、扩展数据库快照、增加 GPTEasy 页面选择器或要求用户手工编辑目录。
- 目录默认值与根级实际 effort仍分开。保留 ADR-0051 已有的官方主机 `high` 映射；未映射供应商省略根级字段，Codex 可以采用目录默认值。兼容默认值不构成新的官方供应商映射。
- 已有根级 `none` 会影响当前请求，但不会清空非空目录列表。下次明确应用供应商时，现有受管迁移清理外部旧值，官方映射写 `high`，未映射供应商交给 Codex 目录默认值。启动和只读检查不改用户配置；消费者重启后读取新目录，已有会话的显式设置仍可能需要在 Codex 中重新选择。
- 当前改动只更新原生当前用户目录；WSL2和独立 Linux 延续现有最小配置协议与共享根级映射，不宣称已为这些环境新增模型目录。
- 目录、配置、凭据和数据库继续使用现有备份、原子写入、Saga与失败恢复。旧图片目录修复继续严格匹配历史 GPTEasy 模板，允许其原来的 null/空 reasoning 对；其他人工能力声明不作为旧模板接受。
- 问题日志记录兼容策略 ID、目录默认 effort和根级目标 effort；根级省略记录为 `omitted`，以区别于显式 `none`。供应商/模型标识保持脱敏，不记录凭据。

## 对既有文档的修订

本决策替代 ADR-0049/0051 中“未知模型输出 null 和空 reasoning 数组”的具体策略。模型发现、已验证能力、选择器兼容声明和实际请求仍保留各自边界。结构化能力快照、逐模型 profile 和用户覆盖属于未实现的后续可选探索，不是本次修复前置条件。

证据与可重复验证命令见 [Codex 0.159.3 选择器验证](../evidence/codex-reasoning-selector-defaults-2026-10-02.md)。当前验证覆盖目录被真实 Codex读取和 App Server返回的选择器选项；不将其称为桌面交互 UAT，也不声称四档已通过真实供应商请求。
