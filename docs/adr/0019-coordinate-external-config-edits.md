# 区分可共存外部修改与管理冲突

GPTEasy 不持续监控或争夺 `config.toml`，只在启动、窗口刷新和执行操作前重新读取实际状态。管理区块之外的修改只要整份 TOML 有效就接受并保留；管理区块内容、边界或供应商 ID 被改动，以及区块重复、嵌套或残缺时进入管理冲突，停止切换和恢复。唯一的兼容例外是桌面 Codex 重写根配置时删除管理区块结束注释：只有开始标记位于文件开头、供应商 ID 与六个受管声明仍连续且结构完整，并且补回结束标记后得到的管理区块指纹与 SQLite 最后应用证据精确一致时，才把它视为可共存外部修改；下一次明确应用会恢复完整边界。任何字段、顺序、作用域或指纹不匹配仍是管理冲突。用户只能在设置中重新选择已验证供应商，查看影响和替换范围、重新备份并明确确认后重新接管；不按名称、地址、模型或被外部改动的 ID 自动匹配。预览或读取后任一受管工件指纹发生变化时，本次操作一律中止并要求从最新状态重试，不做隐式三方合并或无限自动重试。这样允许其他 Codex 设置正常共存，同时避免 GPTEasy 在无法证明所有权时覆盖配置。
