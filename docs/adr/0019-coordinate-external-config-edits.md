# 区分可共存外部修改与管理冲突

GPTEasy 不持续监控或争夺 `config.toml`，只在启动、窗口刷新和执行操作前重新读取实际状态。管理区块之外的修改只要整份 TOML 有效就接受并保留；管理区块内容、边界或供应商 ID 被改动，以及区块重复、嵌套或残缺时进入管理冲突，停止普通切换和恢复。唯一的兼容例外是桌面 Codex 重写根配置时删除结束注释，或把自身根设置插入受管声明与唯一的文件末尾结束注释之间：只有开始标记位于文件开头、供应商 ID 与六个受管声明仍连续且结构完整，并且重建紧凑管理区块后的指纹与 SQLite 最后应用证据精确一致时，才把它视为可共存外部修改；下一次明确应用会恢复紧凑边界并保留插入的桌面设置。任何字段、顺序、作用域、额外供应商 ID、结束注释后非空内容或指纹不匹配仍是管理冲突。有效且可安全解析时，用户可以在设置中重新选择已验证供应商，查看影响和替换范围、重新备份并明确确认后重新接管；不按名称、地址、模型或被外部改动的 ID 自动匹配。无法安全解析时只能进入 ADR-0043 定义的受控重建流程。预览或读取后任一受管工件指纹发生变化时，本次操作一律中止并要求从最新状态重试，不做隐式三方合并或无限自动重试。最近一次操作对某工件的旧、新指纹相同时，该工件没有需要撤销的变化；只有当前供应商、管理指纹和凭据仍能共同确认时，恢复才保留其当前内容并跳过相同字节写盘。这样允许其他 Codex 设置正常共存，同时避免 GPTEasy 在无法证明所有权时静默覆盖配置。
