# 诊断助手通过动作注册表执行受控修复

“帮帮我”中的诊断助手可以规划并推动实质性的配置修复，但只能提交结构化诊断助手动作；GPTEasy 后端动作注册表是最终裁决，动作必须映射到已有的供应商应用、OpenAI 登录模式切换、配置恢复或确定性诊断修复流程。用户按一个可回滚的原子计划明确确认后才执行，执行后重新读取环境实际状态并诊断；模型不得直接写入文件、生成 shell 命令或扩大动作集合。随发行版提供的诊断助手运行手册只作为模型规划依据，并以版本和动作能力标识与后端协同。

## Consequences

- 对话可以完成原先必须从设置页进入的受控配置操作，但不会绕过现有备份、并发检查、原子替换和回滚协议。
- 新的可修复场景必须先实现并测试为后端动作，再加入动作注册表和运行手册；未知或版本不匹配的动作只能转人工处理。
- 诊断助手会话默认临时存在，导出时只包含脱敏诊断、对话和动作结果。
