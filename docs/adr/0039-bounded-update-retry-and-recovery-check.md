# 单一更新源的有界重试与恢复检查

GPTEasy 对 GitCode 正式清单和安装包执行的都是幂等匿名读取。一次网络错误、响应中断，或 HTTP 403、404、408、418、425、429、5xx 不应立即形成持续到进程重启或下一次每日检查的更新失败。每次检查或下载最多尝试三次，采用 1 秒、3 秒的本地退避；服务返回以秒表示的 `Retry-After` 时取它与本地退避的较大值，并把服务端等待上限限制为 30 秒。客户端发送包含 GPTEasy 版本的稳定兼容 User-Agent。

HTTP 成功但正文暂时无法解析为 JSON 时可以重新读取，因为 GitCode WAF 可能以成功响应返回非清单正文。清单能够解析后，稳定版本、目标平台和 HTTPS URL 等语义无效时立即停止；安装包完成下载但 updater 签名无效时也立即停止，不把发布配置错误或信任失败当成普通网络抖动。下载重试丢弃本次内存字节并从头开始，不增加磁盘缓存、断点续传或跨进程待安装包。

单次有界重试耗尽后，检查或下载进入可见失败状态，自动恢复检查依次安排在 5 分钟、30 分钟、2 小时和 24 小时后；任何成功结果都会清零连续失败计数。清单语义无效和签名无效不使用短周期恢复，仍按正常 24 小时节奏检查。内部重试期间继续展示检查或下载状态，只有最终失败才展示错误；用户仍可立即手动重试。

这个决定只提高 ADR-0038 单一 GitCode 信任根内的读取韧性。客户端不回退到 GitHub 或第二个清单端点，不跳过 HTTPS、稳定版本限制或 updater 签名验证，也不改变“自动下载并验签、用户明确确认后才安装”的应用更新边界。本决定落实 #46。
