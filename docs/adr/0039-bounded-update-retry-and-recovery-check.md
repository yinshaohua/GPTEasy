# 更新读取失败后只允许用户手动重试

## 状态

已被 ADR-0045 取代。

本决定取代 #46 原定的单次三次有界重试、`Retry-After` 等待和 5 分钟至 24 小时的短周期恢复检查。ADR-0038 的单一 GitCode 更新信任根和正常每日检查保持不变。

## 决定

每次清单检查或安装包下载只发出一次匿名读取请求。网络错误、响应中断、非成功 HTTP 状态、非 JSON 清单正文或下载失败都立即进入可见失败状态，不在后台等待后重发，也不安排额外的短周期恢复检查。用户可以从更新窗口明确执行“重试”；应用仍按正常 24 小时节奏进行下一次每日检查。

清单稳定版本、目标平台、HTTPS URL 等语义无效时立即失败；安装包下载完成但 updater 签名无效时也立即失败。失败请求不留下跨进程待安装包、磁盘缓存或断点续传状态。客户端不回退到 GitHub 或第二个清单端点，不跳过 HTTPS、稳定版本限制或 updater 签名验证，也不改变“自动下载并验签、用户明确确认后才安装”的边界。

## 原因

隐藏的后台重试会让用户难以判断当前请求是否仍在进行，并使退出、网络切换和再次手动检查之间产生不透明的时序。一次请求对应一次明确结果更容易理解和诊断；瞬时故障由用户可见的重试入口处理，长期更新发现仍由每日检查承担。
