# 会话管理使用 GPTEasy 自有的 App Server 子进程

会话管理通过 GPTEasy 后端独占的 `codex app-server` stdio 子进程访问官方协议，不直接修改 Codex SQLite 或 rollout 文件。该会话服务进程不恢复会话、不发送消息、不审批工具调用，也不承载用户工作，因此不属于 ADR-0026 禁止控制的桌面版或 Codex CLI 用户消费者。

Windows 启动必须无用户可见窗口：后端直接创建进程，管道化 stdin、stdout 和 stderr，并使用 `CREATE_NO_WINDOW`；不得先打开可见的 PowerShell、`cmd.exe` 或终端窗口。若安装入口必须经过命令脚本，承载脚本的命令解释器也必须使用相同的无窗口创建合同。

每个 GPTEasy 应用实例至多拥有一个会话服务进程。正常退出时先停止接收新请求、完成或取消在途请求、关闭子进程 stdin，并在有限宽限期内等待 App Server 因 stdio EOF 自然退出；超时后终止自有进程树。进程从创建起受 Windows Job Object 管理，并启用 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，使 GPTEasy 正常退出、崩溃或被终止时都由系统回收整个自有进程树。

GPTEasy 持久化自有进程的 PID、进程创建时间、规范化可执行文件路径和所有权代次，只用于异常恢复和诊断。下次启动发现旧记录时，先核对所有字段及预期的 App Server 命令身份；只有全部一致才能终止该精确进程，PID 不存在或任一字段不一致时只清理过期记录。不得按进程名、可执行文件名或 `app-server` 参数批量终止进程，也不得接管官方桌面版、IDE、用户 CLI 或其他工具启动的 App Server。

Job Object 是避免真实残留的主保证，启动时的精确身份核对只是防御性恢复。GPTEasy 启动和仅在托盘驻留时不预先启动会话服务进程；用户进入会话管理时才按需启动。离开页面后先等待在途请求完成或取消，再经过短暂空闲宽限期关闭 stdin 并执行上述回收；宽限期内重新进入页面复用原进程。应用明确退出时跳过页面空闲宽限，立即开始优雅关闭和超时回收。

会话服务进程意外退出或协议连接断开时，后端至多自动重启一次，并且只自动重试列表、搜索和详情读取等幂等只读请求。归档、取消归档和永久删除可能已经在响应丢失前生效，绝不自动重试；后端重连后重新读取会话实际状态，由用户决定是否再次操作。
