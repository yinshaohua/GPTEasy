# GPTEasy v1.5.2 变更归档

发布日期：2026-10-17

## 用户可见变更

- 为供应商发现目录中的全部模型统一写入上下文窗口、最大窗口、可用比例和自动压缩字段；未知模型、缺失能力快照和手工加入的模型使用同一套默认目录结构。
- 统一默认值为 `context_window=272000`、`max_context_window=872000`、`effective_context_window_percent=95` 和 `auto_compact_token_limit=null`。自动压缩阈值由目标 Codex 根据目录元数据推导，不新增逐模型容量探测。
- Windows 原生、WSL2 和 Bash/Zsh 导出复用同一个目录生成器；用户明确应用供应商时会迁移旧根级容量键，避免全局设置覆盖模型目录。
- 诊断、切换确认和 WSL2 配置流程显示统一上下文策略；审计日志记录策略、阶段、目标 Codex 数字版本或 `unknown` 和待重启状态，不记录凭据、请求正文或模型指令。

## 验证与范围

- 维护者已确认与本次变更相称的人工测试通过。
- Rust 单元测试、原生环境集成测试、诊断测试、Linux 导出测试、前端检查、前端测试和既有脚本测试均通过；真实 Codex 隔离验收覆盖 Windows 原生和 WSL2 内 Linux 二进制。
- 隔离验收确认双模型目录能够加载，默认有效窗口为 `258400`；小窗口 fixture 观察到 `auto_compact_token_limit=null` 触发自动压缩。该结果验证客户端行为，不代表所有供应商均支持统一默认容量。
- 本次正式交付范围为 Windows x64 当前用户 NSIS 安装包。WSL2、Bash/Zsh 和 macOS 相关能力的声明边界仍以各自文档与实际环境为准；本次不宣称独立原生 Linux 或 macOS 宿主已完成发布验收。

## 安全与兼容性

- `config.toml` 正常只保存 `model_catalog_json` 路径，不新增根级容量覆盖；旧根级容量键只在用户明确应用供应商时迁移，并保留既有备份、原子写入、并发检查、恢复和待重启流程。
- 诊断只读识别根级容量覆盖，不输出覆盖值、不自动改写配置。模型目录字段不等同于供应商容量承诺，后续供应商不兼容反馈需单独设计覆盖机制。
- 安装包可能没有 Authenticode 代码签名，Windows SmartScreen 可能显示警告；updater `.sig`、SHA-256 和发布门禁仍必须通过验证。

## 发布与平台范围

- GitHub 是源码、Tag、Windows x64 构建产物和中文发布说明的权威来源；正式 GitHub Release 发布后，Gitee 按两阶段流程同步同一产物。
- Gitee 标准 `.exe` 必须由维护者在网页中上传。助手只负责提供权威文件路径、等待维护者确认、匿名核对字节并触发第二次同步，不代替维护者操作文件选择器或提交页面。
- Windows ARM64、macOS Intel/Apple Silicon、公证和独立原生 Linux 宿主不在本次正式发布声明内。
