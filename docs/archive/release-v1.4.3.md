# GPTEasy v1.4.3 变更归档

发布日期：2026-09-16

## 用户可见变更

- 供应商完整验证遇到传输失败、响应头或流超时、流意外中断及供应商 5xx 时自动重试一次；认证失败、限流、地址或模型错误和明确的协议不兼容仍直接失败。
- 第二次验证使用新的 HTTP 客户端、连接和 nonce，并从模型发现开始重跑完整三阶段流程；验证弹窗显示当前尝试次数和重试状态。
- 新建普通供应商不再预填示例服务地址，改用浅色占位文字提示用户从供应商处取得 BASE_URL；已有地址和用户输入保持正常文字色。
- 独立 Linux 导出脚本把用户选择供应商视为强制设置授权：先保存完整恢复点，再生成仅含所选供应商的最小配置，避免旧字段、损坏边界或未知 schema 阻止切换；`gpteasy restore` 仍可恢复最近配置。

## 安全与诊断边界

- 自动重试不会从失败步骤续跑，也不会复用第一次工具调用上下文；第一次响应流和 HTTP 客户端先结束，再开始第二次完整验证。
- 问题日志只记录失败阶段、失败分类、尝试次数和是否已重试，不记录服务地址、API Key、请求或响应正文；新增回归测试覆盖日志脱敏。
- 独立 Linux 强制设置仍保留文件身份、Codex 版本、锁竞争和并发修改门禁；旧配置只保存在私有恢复点中，不与新配置拼接。

## 验证记录

- TypeScript 与 ESLint 检查通过。
- React 回归 111 项、Gitee 分发协议 29 项和 Playwright 双视口布局 15 项全部通过。
- 完整 Rust 回归通过；供应商测试覆盖可重试与不可重试分类、完整三阶段重跑、新 nonce、取消和脱敏诊断，Linux 导出测试覆盖强制替换、恢复点、权限、锁和并发修改。
- 可选的交互式 Windows UAT 未作为本次自动验证结果记录。

## 发布与平台范围

- GitHub 继续作为源码、Tag、Windows x64 构建产物和中文发布说明的权威来源；正式 GitHub Release 发布后按两阶段流程同步同一产物到 Gitee。
- Windows 安装包保持当前用户 NSIS 安装和用户确认更新，不执行静默安装。
- Windows ARM64、macOS Intel、Apple Silicon、签名、公证和严格 `~/Applications` 安装仍需对应原生环境验证；本次 Windows x64 发布不宣称这些平台已完成交付。
