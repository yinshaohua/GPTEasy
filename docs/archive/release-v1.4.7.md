# GPTEasy v1.4.7 变更归档

发布日期：2026-09-26

## 用户可见变更

- 自定义供应商生成的 Codex 模型目录统一声明支持 `text` 和 `image` 输入，解除 Codex 在本地对图片请求的提前阻断；这不是图片能力验证，实际请求仍由上游供应商和模型裁决。
- `image detail original` 继续统一关闭，不按供应商、模型名称或模型家族猜测支持情况。
- 升级检查可识别严格匹配旧 GPTEasy 模板的模型目录；用户确认后只备份并更新图片相关字段，不覆盖外部或人工修改的目录，也不会静默重启 Codex。
- 显式应用供应商时，兼容旧版管理区块在根级遗留的 `model_catalog_json`，先移除旧路径再写入当前受管目录，避免重复 TOML 键导致迁移失败。

## 安全与兼容边界

- 图片声明不经过能力探测，不代表模型支持图片生成、视觉理解或任意图片格式；不支持图片的模型可能由上游返回错误，纯文本请求不受影响。
- 目录迁移只在当前活动供应商、配置指针、受管证据和目录内容全部严格匹配时提供；其他情况要求重新应用供应商或人工处理。
- 目录更新继续纳入备份、原子替换、失败恢复和现有消费者重启提示，不写入 API Key。

## 验证记录

- 新增模型目录单元测试，覆盖所有发现模型和补入默认模型的 `text/image` 声明及 `supports_image_detail_original = false`。
- 新增环境工作流回归，覆盖新目录写入、旧根级目录键迁移和失败恢复。
- 新增诊断回归，覆盖旧图片声明的严格识别、用户确认修复、备份、回滚以及拒绝外部/人工修改目录。
- 发布前运行现有 TypeScript、React、Rust、布局、Linux/WSL、发布树和更新信任根门禁；真实供应商图片 UAT 未执行，不记录为通过。

## 发布范围

- 本次正式发布版本为 1.4.7，GitHub Release 是正式发布源。
- Gitee 标准 Windows x64 安装包继续按既定流程由维护者通过网页上传；GitHub Release 发布后，如同步工作流要求人工上传，将提示维护者处理。
- Windows x64 当前用户 NSIS 安装和用户确认更新规则保持不变；其他平台不宣称已完成交付。
