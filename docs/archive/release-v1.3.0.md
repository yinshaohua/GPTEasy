# GPTEasy v1.3.0 变更归档

发布日期：2026-08-27

## 用户可见变更

- “帮帮我”诊断助手使用结构化动作注册表；只有后端已登记的动作才能在用户确认后复用受控配置流程，模型不能执行任意文件写入或 shell 命令。
- 管理冲突无法安全迁移时可以“强制设置”已验证供应商。流程会重新验证，并在后端判定必须重建时再次要求用户确认备份；最终只生成最小受管配置。
- 切换到 OpenAI 登录模式不再要求已有 ChatGPT 凭据。没有可恢复 token 时退出供应商模式，由用户随后从 Codex 官方入口登录。
- Codex 桌面版重启优先请求正常退出；仍驻留时只结束再次复核身份的可信桌面根及其进程树后代。独立 Codex CLI 不被启动、关闭、终止或重启。
- 更新清单或安装包读取失败后立即显示失败，只由用户明确重试；不再在后台执行三次重试或短周期恢复检查，正常每日检查保持不变。

## 被取代的需求

| 旧需求 | v1.3.0 决定 |
| --- | --- |
| #23、#28 禁止主动控制 Codex 桌面版 | 由 ADR-0041 和 #49 取代：仅在用户二次确认后执行可信桌面进程树重启，CLI 继续隔离 |
| #46 自动有界重试和短周期恢复检查 | 由 ADR-0039 当前决定取代：每次读取只尝试一次，失败后手动重试 |
| 管理冲突无法解析时不提供恢复入口 | 由 ADR-0043 取代：重新验证、二次确认、备份后受控重建，不接受任意覆盖内容 |
| 返回 OpenAI 登录模式必须已有 ChatGPT 凭据 | 由 ADR-0014 当前决定取代：允许先退出供应商模式，再从 Codex 官方入口登录 |
| 诊断助手只能解释和生成不可执行计划 | 由 ADR-0042 取代：可提出动作注册表内的结构化动作，用户确认后由后端受控执行 |

## 安全边界

- 所有配置写入继续使用不可变供应商身份、重新验证、环境 revision、备份、原子替换和失败恢复。
- 诊断、日志、Issue 和发布资料不包含 API Key、token、完整配置、认证文件或用户路径。
- 桌面终止集合来自动态发现的受信任 AppX 安装和 PID/创建时间复核；独立 CLI 永不进入该集合。
- 更新继续只信任单一 GitCode 清单端点和内置 updater 公钥，安装仍需用户确认。

## 已知限制与后续安排

- 发布后真实匿名复核发现，客户端内置的 GitCode 稳定分支 Raw 清单地址可能返回 HTTP 403；Contents API、不可变 blob 和 Release 附件均可读取，因此重复上传附件不能解决该问题。
- v1.3.0 不包含清单通道回退。更新检查受影响时，用户需要从 GitHub Releases 或 GitCode Releases 手工下载安装包。
- 后续优化由 [#53](https://github.com/yinshaohua/GPTEasy/issues/53) 跟踪：Raw 读取因网络或 WAF 失败时，匿名读取同一 GitCode 分发仓库的 Contents API/Base64 清单。它不回退到 GitHub、不使用客户端 Token，也不放宽 updater 签名和用户确认安装门禁。
- 实施 #53 时同步更新 ADR-0038/0039；在新版本发布前，不把计划中的回退描述为 v1.3.0 已具备能力。

## 验证记录

- 真实 Windows 桌面测试观察到旧 Codex 桌面根及其后代退出，并扫描到新的可信桌面根；独立 Codex CLI 的 PID 与创建时间保持不变。
- 本地安装的 Windows x64 NSIS 测试包验证了新增桌面重启稳定消息；正式 Release 使用从干净 `main` 构建并通过 updater 签名验证的同一候选产物。
- 自动化门禁覆盖 Rust、React、布局、发布合同、单一更新信任根和 Windows 综合验收；具体候选结果由发布候选 manifest 与 GitHub Release 附件共同保存。
