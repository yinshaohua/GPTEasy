# 已开发功能归档（2026-08-09）

本文记录旧 GSD 管理退出时，仓库中已经存在并有代码或自动化测试支撑的功能。它只用于了解历史交付，不定义后续范围、优先级或完成状态；后续工作由 GitHub Issues 和 grilling 系列管理。

**归档基线**：`main` 提交 `2e347d5`（2026-08-09）。

## 桌面应用基础

- 已建立 Tauri 2、Rust、React 和 TypeScript 桌面应用，当前交付目标为 Windows x64 当前用户安装。
- 前端只通过 Tauri command 使用后端能力，不直接访问文件、SQLite、网络或进程。
- 已实现“供应商”和“Codex 环境”两页设置界面，包含启动阻断、忙碌、错误、确认和空状态。
- 已实现系统托盘驻留、设置窗口显示、明确退出、首次关闭提示和托盘菜单刷新。

## 本地状态

- 已实现当前用户应用状态目录和 SQLite 最小 schema，保存供应商目录、应用模式、最近应用证据、待重启信息与单个未完成配置操作。
- 已实现追加式迁移、数据库身份和 schema 校验、外键与完整性检查；未知未来版本、损坏或不符合合同的数据库会停止写入。
- 迁移前会创建一致性备份并只保留最近三份；数据库缺失或损坏时可从最近有效备份恢复，同时保留异常原件。
- 已提供正式 v001 数据库 fixture，并以真实文件测试覆盖初始化、迁移、备份、恢复和失败关闭。

## 供应商管理

- 已实现供应商新增、列表、查看凭据、复制凭据、改名、重新验证、更新和删除。
- 供应商名称去除首尾空白后不区分大小写唯一；供应商 ID 在改名和更新中保持不变。
- 未验证输入不会持久化；失败、取消、离页或丢弃验证都不会改变供应商目录和 Codex 环境。
- 非当前供应商可在重新验证后更新；当前供应商的关键配置更新会与 Codex 环境应用作为同一业务操作处理。

## 供应商验证

- 已实现模型发现和默认模型选择，远程地址仅允许 HTTPS，HTTP 只允许回环地址。
- 已实现 Responses API 流式验证，包括 SSE 分片、严格工具调用、参数校验和 nonce 回传闭环。
- 已区分认证、限流、服务端、协议、首事件超时、整体超时、传输和用户取消等失败类别，普通错误不包含 API Key。
- 验证回执以组合指纹绑定服务地址、API Key 和模型，并带有效期及并发修改校验，只有匹配的验证结果可以保存。

## Codex 环境管理

- 已实现当前用户 Codex 配置、凭据载体和 OpenAI 登录状态检查；只读预览不会创建缺失配置。
- 已实现供应商模式与 OpenAI 登录模式切换。GPTEasy 不读取、备份、保存或删除 OpenAI 令牌。
- 首次接管外部配置前会展示受影响工件并要求确认；写入保留非 GPTEasy 字段，建立唯一的 GPTEasy 管理区块。
- 已实现管理区块漂移、重复或损坏标记、无效 TOML、非 UTF-8、凭据形态异常、重定向文件及并发修改检测；这些情况在备份或写入前停止。
- 配置和凭据写入采用同目录临时文件、同步落盘、原子替换和复读校验；每次操作保留最近五份完整配置备份。
- 已实现“恢复上次配置”，只恢复最近一次已完成操作影响的工件，并拒绝覆盖操作后又被外部修改的内容。

## 一致性与崩溃恢复

- SQLite 与 Codex 工件之间通过单个未完成配置操作记录意图、阶段、旧新指纹和备份位置。
- 启动时可根据磁盘实际状态前滚、回滚或进入管理冲突，不会用数据库期望值静默覆盖未知外部修改。
- 供应商切换、OpenAI 登录模式切换和恢复上次配置共用恢复协议，并以故障注入矩阵覆盖各提交边界。
- 回滚失败、混合工件状态和未知指纹会保留现场并阻止继续写入。

## Codex 消费者与待重启

- 已实现 Windows 桌面 Codex 与 Codex CLI 进程识别，结合进程名、可信路径、父子关系、用户身份、启动时间和访问状态分类。
- 配置变更不会终止或自动重启 Codex 消费者；检测到运行中、无消费者或检测结果未知时均通过确认流程处理。
- 已实现待重启状态，并以 PID 和启动时间跟踪旧进程身份，避免 PID 复用导致误判。
- 只有可信扫描确认切换前的消费者都已退出后才清除待重启；访问受限、上下文损坏或切换期间新进程出现时保持待重启。
- 托盘可显示当前环境和已验证供应商，并复用环境切换的确认、并发版本及恢复边界。

## 验证覆盖

- Rust 集成测试覆盖供应商网络协议、SQLite 状态、Codex 安全写入、崩溃恢复、消费者识别、待重启和启动协调。
- 架构测试约束前端资源权限，以及 Windows x64 当前用户 NSIS 打包配置。
