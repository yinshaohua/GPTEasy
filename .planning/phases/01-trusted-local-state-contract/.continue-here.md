## Critical Anti-Patterns (do NOT repeat these)

- 不要把无测试输出的 2 分钟 Cargo 超时记录成 RED；给冷构建足够时间并等待明确失败证据。
- 不要通过 lock 文件是否存在或 owner metadata 判断锁所有权；只相信 OS file lock primitive。
- 不要让 verify 删除数据库、备份、marker 或 run-scoped 状态；只有显式 cleanup 可以删除匹配 run。
- 不要接受 CLI 路径参数，也不要清理未通过固定根、opaque run ID 和 marker 三重验证的路径。
- 不要在测试中直接导入 `StateStore`、repository 或 `rusqlite` 旁路 production CLI/IPC seam。
- 不要提交 `.planning/config.json` 或 `.planning/research/.cache/*`。
