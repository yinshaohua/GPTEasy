# Requirements: GPTEasy

**Defined:** 2026-08-05
**Core Value:** 非技术用户能够验证供应商，并在保留既有 Codex 配置且可恢复的前提下，可靠地切换各受管环境使用的 API 服务。
**Baseline:** `CONTEXT.md`、`docs/adr/` 和 `docs/ui/UI-SPEC.md` 是已确认且锁定的需求来源。
**Release Strategy:** 所有 v1 要求作为一个完整首版统一发布；内部阶段不作为范围不完整的正式版本发布。

## User Stories

- 作为不熟悉 Codex 配置文件的用户，我希望通过可理解的页面配置并验证供应商，从而只保存真正可供 Codex 使用的配置。
- 作为同时使用统一 ChatGPT 桌面应用和本机 Codex CLI 的用户，我希望一次切换原生 Codex 环境，并清楚知道是否需要重启正在运行的 Codex。
- 作为 Windows 与 WSL2 用户，我希望为每个 WSL2 环境独立选择供应商，并且 GPTEasy 不会擅自改变发行版原有的运行状态。
- 作为外部 Linux 用户，我希望复制一份不依赖 GPTEasy 或额外运行时的脚本，之后仍能长期独立切换供应商。
- 作为已有自定义 Codex 配置的用户，我希望供应商切换只修改 GPTEasy 管理的内容，并能在失败或意外退出后恢复。
- 作为保存明文供应商凭据的用户，我希望能完整查看、复制和导出 API Key，同时确保日志、错误和诊断资料不会泄露凭据。
- 作为 Windows 或 macOS 用户，我希望通过托盘快速切换原生 Codex 环境，并在需要详细配置时打开一致、清晰、可访问的设置窗口。
- 作为长期使用者，我希望应用升级能够保留供应商、凭据和环境状态，并且更新安装始终由我确认。

## v1 Requirements

### 本地状态与配置安全

- [x] **STATE-01**: 用户关闭并重新打开 GPTEasy 后，供应商目录、验证状态、各受管环境的当前供应商和应用设置保持不变。
- [x] **STATE-02**: 供应商、供应商凭据、当前状态和诊断日志只保存在当前用户本机，应用不要求产品账户，也不默认上传这些数据。
- [x] **STATE-03**: 用户从任一正式历史版本升级时，应用能够通过永久保留的顺序迁移直接升级现有 SQLite 数据库。
- [x] **STATE-04**: 数据库迁移前自动创建完整备份并默认保留最近三份；迁移失败时事务回滚，应用不能通过清空用户数据继续运行。
- [x] **STATE-05**: 旧版 GPTEasy 遇到更高版本数据库时拒绝写入，降级只能通过恢复升级前备份完成。
- [ ] **STATE-06**: GPTEasy 修改 Codex 配置时只改变供应商相关字段或明确的 GPTEasy 管理区块，并保留用户其他设置、未知字段和可保留格式。
- [ ] **STATE-07**: 每个受管环境在实际修改 Codex 配置前创建带时间戳的备份并默认保留最近五份，写入使用同目录临时文件和平台安全的原子替换。
- [ ] **STATE-08**: 当配置存在外部并发修改、损坏、重复管理区块、歧义、权限错误、磁盘错误或中断时，应用停止修改、不给出假成功，并提供明确的恢复或重试状态。

### 供应商目录与生命周期

- [ ] **PROV-01**: 用户可以创建只包含名称、服务地址、API Key 和默认模型的标准供应商。
- [ ] **PROV-02**: 远程供应商服务地址必须使用 HTTPS；只有 `localhost`、`127.0.0.1` 和 `[::1]` 回环地址允许使用 HTTP，且用户不能绕过该限制。
- [ ] **PROV-03**: 每个供应商创建时获得不可变供应商 ID，修改显示名称、服务地址、API Key 或默认模型不会改变其身份。
- [ ] **PROV-04**: DayWay 作为内置推荐供应商模板始终位于设置界面的供应商列表第一项，并展示锁定的推荐说明和官网入口。
- [ ] **PROV-05**: 未配置推荐供应商不能参与切换、不能成为当前供应商，也不显示在托盘供应商列表中。
- [ ] **PROV-06**: DayWay 模板更新可以直接更新未配置模板，但不能静默覆盖已验证 DayWay 的服务地址、API Key 或默认模型。
- [ ] **PROV-07**: 用户只有在供应商完成全部供应商验证后才能保存其关键配置并将其加入供应商目录。
- [ ] **PROV-08**: 用户修改服务地址、API Key 或默认模型后必须重新完成供应商验证，验证成功前不能保存这些修改。
- [ ] **PROV-09**: 已验证供应商的关键配置修改验证失败时，原来的已验证配置和所有环境引用保持可用。
- [ ] **PROV-10**: 用户只修改名称等不影响服务能力的字段时，可以直接保存而无需重新验证。
- [ ] **PROV-11**: 已验证供应商更新成功后，新配置自动传播到所有当前使用该供应商的原生 Codex 环境和 WSL2 环境，并逐环境报告结果。
- [ ] **PROV-12**: 当前仍被原生 Codex 环境或任一 WSL2 环境使用的供应商不能直接删除；外部 Linux 切换脚本不阻止删除且不会被远程修改。

### 供应商验证

- [ ] **VALD-01**: 服务地址和 API Key 完整后，用户可以获取供应商当前可用模型；条件不满足时操作保持禁用并说明原因。
- [ ] **VALD-02**: 用户必须从实际获取的模型中选择默认模型，未选择时完整供应商验证保持禁用并说明原因。
- [ ] **VALD-03**: 供应商验证依次执行默认模型确认、Responses API 流式响应和工具调用闭环三项检查。
- [ ] **VALD-04**: 任一验证步骤失败后停止后续步骤，用户不能跳过失败项或把部分成功结果当作已验证。
- [ ] **VALD-05**: 验证页面逐项展示等待、进行中、成功或失败状态，并且状态不只依赖颜色表达。
- [ ] **VALD-06**: 验证失败时默认展示面向非技术用户的简短说明，并允许展开查看 HTTP 状态码和脱敏技术详情。
- [ ] **VALD-07**: 用户可以复制脱敏错误信息，但错误、日志和复制内容不包含 API Key、完整请求、模型输出或完整响应正文。
- [ ] **VALD-08**: 全部验证成功后记录并展示验证时间；该时间只表示最近一次完整验证成功，不表示持续健康监控。

### 原生 Codex 环境

- [ ] **NATV-01**: 应用能够检测当前用户的统一 ChatGPT 桌面应用 Codex 功能和本机原生 Codex CLI，并将它们作为同一个原生 Codex 环境管理。
- [ ] **NATV-02**: 未检测到宿主应用但存在本机 Codex CLI 时，用户仍可管理和切换原生 Codex 环境，并能看到宿主应用安装建议。
- [ ] **NATV-03**: 宿主应用和本机 Codex CLI 都未检测到时，供应商管理、WSL2 管理和 Linux 切换脚本导出仍可使用，但原生环境托盘切换不可用。
- [ ] **NATV-04**: 原生 Codex 配置无法唯一匹配已保存供应商时，应用将其展示为外部配置，不自动覆盖，也不将其视为已验证供应商。
- [ ] **NATV-05**: 用户可以让原生 Codex 环境在代理 API 模式和原厂登录模式之间切换；代理 API 模式为默认模式，原厂登录模式只能在设置中主动启用。
- [ ] **NATV-06**: 首个供应商验证成功后，应用自动将该供应商设为原生 Codex 环境当前供应商并切换到代理 API 模式。
- [ ] **NATV-07**: 已经存在已验证供应商时，新供应商验证成功后只加入供应商目录，不自动改变原生 Codex 环境或任何 WSL2 环境的当前供应商。
- [ ] **NATV-08**: 原生 Codex 环境没有运行中 Codex 进程时，用户可以从设置窗口或托盘立即切换到任一已验证供应商。
- [ ] **NATV-09**: 原生 Codex 环境存在运行中 Codex 进程时，主动切换在写入配置前让用户选择立即重启、稍后重启或取消，并展示当前供应商、目标供应商、进程类型和任务中断警告。
- [ ] **NATV-10**: 用户取消运行中切换时，应用不修改 Codex 配置、SQLite 环境状态或当前供应商。
- [ ] **NATV-11**: 用户选择稍后重启时，配置切换完成并进入待重启状态，应用不主动终止桌面 Codex 或本机 Codex CLI 进程。
- [ ] **NATV-12**: 用户选择立即重启时，应用只对可安全控制的桌面宿主应用执行可验证的关闭和重新启动；无法安全恢复的 CLI 进程保持明确待重启状态。
- [ ] **NATV-13**: 已确认的供应商配置传播在写入后只允许用户选择立即重启或稍后重启，不能把已经保存的供应商更新取消回旧配置。

### 托盘与设置界面

- [ ] **UX-01**: 设置窗口使用供应商、WSL2、Linux 脚本和设置四个侧边栏页面；macOS 不显示 WSL2 页面，也不设置独立仪表盘首页。
- [ ] **UX-02**: 供应商列表使用紧凑卡片展示名称、推荐标签、服务主机名、默认模型、验证状态、最近验证时间和当前使用状态，不展示 API Key，不使用分页。
- [ ] **UX-03**: 当供应商数量达到实施阶段确定并记录的统一阈值时，列表提供搜索，阈值在 Windows 与 macOS 上保持一致。
- [ ] **UX-04**: 查看、新增和编辑供应商使用同一个完整单页结构；字段直接可编辑，未修改时保存禁用，关键字段未重新验证时不能保存。
- [ ] **UX-05**: 新增供应商时 API Key 默认明文显示；打开已保存供应商时默认隐藏，用户可以完整显示和复制，离开后再次打开恢复隐藏。
- [ ] **UX-06**: 用户离开存在未保存修改的供应商页面时可以选择放弃或继续编辑；删除操作位于页面底部危险区域并要求明确确认。
- [ ] **UX-07**: 首次启动直接进入供应商页面，通过欢迎横幅展示原生 Codex 环境检测结果、供应商配置提示、首次自动切换说明和登录启动选择，不使用多步骤欢迎向导。
- [ ] **UX-08**: 所有空状态都说明当前状态并提供明确下一步，包括无供应商、无原生 Codex 环境、无 WSL2 环境和无可导出供应商。
- [ ] **UX-09**: 托盘只列出已验证供应商并只切换原生 Codex 环境；顶部展示当前供应商、原厂登录模式、外部配置或待重启状态，下方只提供“设置…”和“退出 GPTEasy”。
- [ ] **UX-10**: 页面内状态、Toast、系统通知和模态对话框按 UI 基线分工，同一结果不重复通知，任何通知和错误正文都不包含 API Key 或完整服务地址。
- [ ] **UX-11**: 用户可以在跟随系统、浅色和深色主题之间切换，并可以在简体中文和英语之间切换；修改后设置窗口、托盘、原生对话框和通知同步生效。

### WSL2 环境

- [ ] **WSL-01**: Windows 用户可以在 WSL2 页面看到每个 WSL2 环境的发行版名称、默认用户、运行状态、当前供应商状态和待重启状态。
- [ ] **WSL-02**: 被动检测 WSL2 环境时不启动已停止的发行版，也不修改其 Codex 配置。
- [ ] **WSL-03**: GPTEasy 只管理每个 WSL2 环境的 WSL2 默认用户，不扫描或管理同一发行版中的其他 Linux 用户。
- [ ] **WSL-04**: 新检测到但尚未选择供应商的发行版展示为未配置 WSL2 环境，不自动继承原生 Codex 环境当前供应商。
- [ ] **WSL-05**: 每个 WSL2 环境独立保存当前供应商，切换一个环境不会改变原生 Codex 环境或其他 WSL2 环境。
- [ ] **WSL-06**: 用户可以通过只包含已验证供应商的行内选择器立即切换单个运行中的 WSL2 环境，并查看成功、失败或待重启结果。
- [ ] **WSL-07**: 用户切换已停止的 WSL2 环境前会看到临时启动提示；应用完成或失败后恢复其原有停止状态。
- [ ] **WSL-08**: 操作期间检测到用户并发活动或无法确认临时启动所有权时，应用不强制停止发行版，并明确报告恢复状态。
- [ ] **WSL-09**: 用户可以选择一个已验证供应商并确认受影响发行版后执行“应用到全部 WSL2”，批量结果逐发行版展示成功、失败或待重启。
- [ ] **WSL-10**: WSL2 中仍有使用旧配置的 Codex 进程时，环境进入 WSL2 待重启状态，应用提示用户重启但不主动终止这些进程。

### Linux 切换脚本

- [ ] **LNX-01**: 用户可以分别生成 Bash 4+ 或 Zsh 5+ 的 Linux 切换脚本，并选择简体中文或英语交互文本。
- [ ] **LNX-02**: Linux 切换脚本始终包含导出时全部已验证供应商及其明文供应商凭据，不包含未配置或未验证供应商，也不提供供应商子集选择。
- [ ] **LNX-03**: 脚本不依赖 Python、Node.js、第三方解析器、辅助二进制或 GPTEasy 可执行文件，复制到其他 Linux 系统后可长期独立使用。
- [ ] **LNX-04**: 用户复制或保存脚本前必须看到固定的明文 API Key 风险提示，脚本不会被自动写入本机或远程 Linux 的 Shell 启动文件。
- [ ] **LNX-05**: 用户调用脚本中的交互式 Linux 供应商选择 function 时，可以看到目标 Linux 当前供应商和可用供应商，并可直接退出而不修改配置。
- [ ] **LNX-06**: 用户选择供应商后，function 只修改当前 Linux 用户 Codex 配置中的 GPTEasy 管理区块，并保留其他配置。
- [ ] **LNX-07**: Linux function 写入前创建带时间戳备份并默认保留最近五份，使用安全权限、同目录临时文件、原子替换和写后校验。
- [ ] **LNX-08**: GPTEasy 管理区块损坏、重复或存在歧义时，function 停止修改并保留原配置，不自动修复或重写整份 TOML。
- [ ] **LNX-09**: “复制脚本”为主操作，“保存为文件”为次操作；保存文件分别使用 `gpteasy-providers.bash` 或 `gpteasy-providers.zsh`，并提供简短手工安装说明。

### 诊断、更新与应用生命周期

- [ ] **OPS-01**: 应用在本地保存脱敏诊断日志并默认只保留最近七天，日志不记录完整请求、模型输出或供应商凭据。
- [ ] **OPS-02**: 用户可以主动生成包含应用和环境摘要及诊断日志的诊断导出，导出不包含供应商凭据、SQLite 数据库、配置备份或 Linux 切换脚本。
- [ ] **OPS-03**: 诊断资料默认不上传；复制错误、技术详情、批量结果和系统通知使用同一脱敏边界。
- [ ] **OPS-04**: 应用启动后每天最多检查一次新版本，更新检查不上传供应商目录、API Key 或当前供应商状态。
- [ ] **OPS-05**: 发现更新时应用提示用户，下载和安装都由用户确认，不执行静默安装。
- [ ] **OPS-06**: 更新退出前等待配置操作到达安全提交点、刷新持久化状态并处理 WSL2 临时启动恢复，不能让安装过程截断正在进行的配置事务。
- [ ] **OPS-07**: 登录启动默认关闭，首次使用时提示用户选择；用户之后可以在设置中启用或禁用，并看到实际系统状态。
- [ ] **OPS-08**: 关闭设置窗口后，应用按首次确认结果继续托盘驻留；只有托盘中的明确退出操作结束 GPTEasy。
- [ ] **OPS-09**: 系统通知只用于窗口不可见时的托盘切换结果、后台批量操作完成、版本更新和稍后重启提醒，且不与应用内 Toast 重复。

### 平台、发布与无障碍

- [ ] **REL-01**: Windows 正式版本支持 Windows 10 22H2 或更高版本的 x64 和 ARM64，并以当前用户范围安装、更新和保存应用数据。
- [ ] **REL-02**: macOS 正式版本支持 macOS 14 或更高版本的 Intel 和 Apple Silicon，并以当前用户可安装、可更新的方式分发。
- [ ] **REL-03**: Linux 不提供独立 GUI 安装物，只验收受支持 Shell 上的独立 Linux 切换脚本。
- [ ] **REL-04**: 所有核心供应商配置、验证、切换、WSL2 管理、脚本导出和设置操作都可以通过键盘完成，Tab 顺序与视觉顺序一致。
- [ ] **REL-05**: 核心界面提供屏幕阅读器可识别名称、清晰焦点环、至少 WCAG AA 的颜色对比度，并且状态不只依赖颜色。
- [ ] **REL-06**: 在 200% 系统缩放、高对比度模式和减少动态效果设置下，用户仍能完成所有核心操作。
- [ ] **REL-07**: Windows 与 macOS 发布工件分别通过代码签名、平台信任验证和 Tauri updater 内容签名，旧正式版本能够安全升级到当前版本。
- [ ] **REL-08**: 只有 Windows x64/ARM64、macOS Intel/Apple Silicon、真实 WSL2、Bash/Zsh、双语、无障碍、数据库升级、配置故障恢复、安装和更新门禁全部通过后，才能发布完整首版。

## v2 Requirements

当前没有已承诺的 v2 需求。锁定基线明确排除的能力不会因为未进入 v1 而自动成为 v2 承诺；如未来纳入，必须重新评估需求、风险和路线图。

## Out of Scope

| Feature | Reason |
|---------|--------|
| 产品账户、云端存储和云同步 | 首版采用完全本地模式，避免明文供应商凭据进入服务端和同步链路 |
| 自动跨设备迁移和 Linux 脚本回导 | 首版不提供迁移格式，Linux 切换脚本是独立使用物而非 GPTEasy 回导文件 |
| Linux 独立 GUI | Linux 首版只提供 Bash/Zsh 独立 function |
| 本地 API 代理网关 | 锁定为直接修改 Codex 配置，避免 GPTEasy 成为持续请求依赖 |
| 机器级公共配置、其他用户配置和自定义配置路径 | 首版只管理当前操作系统用户及各 WSL2 环境默认用户的默认配置 |
| WSL2 自动跟随原生 Codex 环境和托盘 WSL2 快捷切换 | 原生 Codex 环境与每个 WSL2 环境保持独立当前供应商 |
| Fish、Nushell、仅 POSIX sh 和带额外运行时依赖的脚本 | 首版只支持 Bash 4+、Zsh 5+ 和常见基础命令 |
| 无 Key 的脚本导出模式 | 独立脚本必须自包含供应商配置和明文凭据 |
| 自定义 Header、组织或项目标识等高级认证字段 | 首版标准供应商只包含服务地址、API Key 和默认模型 |
| 管理旧版宿主应用供应商 | 首版只检测旧版宿主应用并提示迁移 |
| 自动终止 Codex 进程 | 用户必须决定立即重启、稍后重启或取消，应用不静默中断任务 |
| 持续供应商健康监控 | 验证时间只表示最近一次完整验证成功 |
| 覆盖外部配置或自动修复歧义配置 | 无法安全匹配或修改时必须保留实际状态并停止写入 |
| 静默下载、安装或更新 | 更新始终由用户确认 |
| 聊天应用式仪表盘、营销卡片和持续动画 | UI 锁定为轻量、克制、托盘优先的原生系统工具体验 |
