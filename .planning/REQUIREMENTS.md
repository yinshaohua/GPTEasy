# Requirements: GPTEasy v0.1

## Architecture And State

- [ ] **ARCH-01**: 应用以 Windows x64 当前用户安装的 Tauri 2 桌面程序交付，业务实现使用 Rust 和 TypeScript/React。
- [ ] **ARCH-02**: Rust 是供应商规则、网络验证、SQLite、Codex 工件和进程状态的唯一权威；React 只调用窄而强类型的完整用例，不直接访问这些资源。
- [ ] **ARCH-03**: 应用直接管理当前用户默认 Codex 配置和目标版本支持的用户级凭据载体，不运行本地 API 网关，不创建环境变量，也不支持自定义路径。
- [ ] **STATE-01**: SQLite 只保存当前已验证供应商及明文 API Key、最后应用证据、至多一个未完成配置操作和首版必要应用状态；不保存草稿、供应商历史、软删除或未来能力占位。
- [ ] **STATE-02**: 数据库使用代码内追加式顺序迁移；迁移前通过 SQLite Backup API 创建并校验一致备份，保留最近三份，每个正式 schema 都有脱敏历史 fixture。
- [ ] **STATE-03**: 全新安装可以初始化数据库；已有安装遇到数据库缺失、损坏、迁移失败或更高 schema 时停止普通操作，保留原文件并自动恢复最新有效备份，不能静默创建空库。
- [ ] **STATE-04**: SQLite 是供应商目录和恢复信息的权威，Codex 配置与凭据载体是环境实际状态；启动、刷新、恢复和操作前后都必须协调，不一致时不自动用数据库覆盖磁盘。

## Verified Providers

- [ ] **PROV-01**: 用户可以输入名称、服务地址、API Key 和默认模型创建供应商；保存时生成不可变 UUID，名称去除首尾空白后不区分大小写唯一。
- [ ] **PROV-02**: 远程服务地址必须使用 HTTPS，只有 `localhost`、`127.0.0.1` 和 `[::1]` 允许 HTTP；地址禁止用户信息、查询和片段，规范化后仍保留用户给定的路径前缀，任何重定向都失败。
- [ ] **PROV-03**: 默认模型只能从当前服务地址和 API Key 实际返回的模型列表选择；模型发现失败或没有可用模型时不能验证或保存。
- [ ] **PROV-04**: 供应商验证必须完成 Responses API 流式工具调用闭环，校验严格 JSON Schema、工具名、调用 ID、参数和随机 nonce，回传工具结果后从后续流中得到同一 nonce。
- [ ] **PROV-05**: 只有完整验证成功且用户明确保存后供应商才进入目录；失败、取消、离页或关闭窗口不持久化输入，不创建配置、备份或未完成操作。
- [ ] **PROV-06**: 非当前供应商关键字段修改后必须重新验证再保存；当前供应商的关键字段只能通过“保存并应用”可恢复地同时更新供应商记录和 Codex 环境，任一步失败保留完整旧状态；仅改名可以直接保存。
- [ ] **PROV-07**: 验证状态不自动过期，用户可以手动重新验证；每个供应商只保留当前已验证版本，当前供应商不能删除，其他供应商删除后不改写历史配置备份。
- [ ] **UI-01**: “供应商”页使用无搜索、无分页、无数量上限的紧凑列表和详情编辑区，API Key 默认隐藏且只在用户明确操作后完整显示或复制。

## Codex Environment

- [ ] **CONF-01**: 应用启动、供应商验证和供应商保存不得创建缺失的 `config.toml`；只有用户明确切换供应商或 OpenAI 登录模式时才允许创建受管工件。
- [ ] **CONF-02**: 没有有效 GPTEasy 供应商 ID 的配置视为外部配置；用户选择已验证供应商、查看替换范围并确认后才能备份接管，其他有效设置必须保留。
- [ ] **CONF-03**: 管理区块被改动、重复、嵌套或损坏时进入管理冲突；用户只能在设置中重新选择已验证供应商并确认接管，TOML 或字段归属无法安全判断时拒绝写入。
- [ ] **CONF-04**: 预览或读取后任一受管工件指纹变化时中止并要求重试，不自动合并；每次正式写入前完整备份将被改写的配置和凭据载体及其存在性，配置备份保留最近五份。
- [ ] **CONF-05**: 配置变更串行执行，通过同目录暂存、平台安全替换和复读校验提交；单个未完成操作足以在重启后按旧指纹、新指纹或第三种指纹收敛到旧状态、新状态或管理冲突。
- [ ] **CONF-06**: “恢复上次配置”只恢复最近一次 GPTEasy 修改前的受管工件；原文件不存在时恢复为不存在，发现外部改动时拒绝，成功后协调 SQLite 最后应用证据但不删除供应商目录记录。
- [ ] **MODE-01**: 当前用户 Codex 环境具有互斥的供应商模式和 OpenAI 登录模式；切换到 OpenAI 登录模式只能在“Codex 环境”页执行，必须检测到 Codex 已有本地登录凭据，且不得读取、保存或删除 OpenAI 令牌。
- [ ] **UI-02**: “Codex 环境”页展示当前模式、当前供应商、消费者、外部配置、管理冲突和待重启，并提供模式切换、接管、重新接管和恢复上次配置。

## Runtime And Desktop UX

- [ ] **RUN-01**: 应用检测桌面 Codex 和 Codex CLI，并用名称、可执行路径、父子关系、PID 与启动时间等证据识别；不能只按进程名或 PID 判断。
- [ ] **RUN-02**: 运行中的消费者、检测不可信或未检测到消费者时，切换前只提供继续或取消；继续后允许写入并保守进入待重启，应用不得关闭、终止、重启或恢复消费者。
- [ ] **RUN-03**: 只有可靠检测确认切换前消费者全部退出后才清除待重启；托盘驻留期间仅在待重启存在时低频观察，新启动的消费者不阻塞清除。
- [ ] **RUN-04**: 托盘顶部展示环境状态，中间只列已验证供应商，底部只有“设置...”和“退出 GPTEasy”；正常受管状态点击不同供应商立即切换，风险场景确认，外部配置或管理冲突只能进入设置处理。
- [ ] **RUN-05**: OpenAI 登录模式只能从设置启用，但可以从托盘选择已验证供应商并确认返回供应商模式；模式变化和进程风险必须合并为一次确认。
- [ ] **UI-03**: 设置窗口关闭后应用托盘驻留，第一次关闭只通知一次，只有明确退出或 Windows 会话结束才结束程序；首版不提供登录启动。
- [ ] **UI-04**: 界面只提供简体中文并跟随 Windows 主题；键盘、屏幕阅读器、200% 缩放、高对比度和减少动态效果验收通过；应用不写持久诊断日志，也不生成诊断导出。

## Acceptance And Delivery

- [ ] **REL-01**: 自动化使用本地模拟供应商、隔离 Codex 目录和进程 fixture，至少建立两个不同名称和 UUID 的已验证供应商，并覆盖配置缺失、OpenAI 登录、有效外部配置和损坏或歧义配置四种起点。
- [ ] **REL-02**: 自动化在未完成操作登记、备份完成、部分工件替换、全部工件替换和 SQLite 提交边界注入失败，证明不会产生部分成功、密钥泄漏或虚假当前状态。
- [ ] **REL-03**: 发布前人工 UAT 在一次性 Windows x64 当前用户环境中，使用至少一个真实标准供应商、当前支持的真实 Codex CLI 和桌面 Codex完成验证、切换，并证明新进程读取目标配置。
- [ ] **REL-04**: 可验收构建可以是未签名的 Windows x64 当前用户安装包；任何正式对外发布必须具有有效 Authenticode 签名，并验证安装、覆盖安装、卸载和用户数据保留。

## Out Of Scope

- Windows ARM64、macOS、WSL2、Linux 切换脚本和 DayWay。
- 自动更新、更新检查、updater、登录启动、持久诊断日志和诊断导出。
- 产品账户、云同步、跨设备迁移、遥测和崩溃上传。
- 本地 API 代理、环境变量切换、机器级或自定义 Codex 配置路径。
- 搜索、分页、多语言、手动主题和供应商高级认证字段。
- 自动重启或终止 Codex 消费者。

## Definition Of Done

- 34 项活动需求全部通过自动化或明确标记的人工 UAT 证据。
- 目标 Codex 版本的配置路径、字段、凭据载体和两类消费者读取行为在实现时重新验证。
- 自动化故障矩阵与真实供应商闭环都通过；旧 Spike 或模拟结果不能单独替代真实 UAT。
- 工作树不存在旧产品源码、旧 88 项活动路线或把归档完成状态计入当前进度的入口。
